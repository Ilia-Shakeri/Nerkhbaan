Telegram price ingestion setup — source/docs 2.8.16, reviewed 2026-10-28

Required product scope; real channel/group collection is not yet accepted.
Authoritative Persian guide: ../../docs/telegram-ingestion-guide-fa.md
Acceptance and flowcharts: ../../docs/project-completion-roadmap-fa.md

1. Owner selects an accessible channel and group and establishes permitted collection, storage and display/history scope. Do not assume public access grants reuse rights.
2. Reading uses TELEGRAM_API_ID, TELEGRAM_API_HASH and TELEGRAM_SESSION_STRING. Keep them only in a restricted private environment. login.py prints the session; run only in a private unrecorded terminal. Never paste phone, code, password or session into chat, logs or Git.
3. Create sources through the administrator panel with numeric channel identity, permitted instruments, parser, confidence, age, role and explicit confirmation. TELEGRAM_CHANNELS is unused by the current worker; database allowlisting selects sources.
4. Supply current source grants as telegram:<database-source-id> through PRICING_RIGHTS_MANIFEST_PATH. Worker requires collect/store. API display/history permissions are separately checked. Mount the validated manifest read-only in both worker and API; a path variable alone does not mount a file. The current worker compose service needs this deployment wiring verified/completed.
5. The API additionally checks telegram_source_enabled. Consumer roles verifier/fallback do not make Telegram an automatic primary source. A bot token for sending alarms does not replace the reading account session.
6. Before enabling the telegram profile, complete and test actual group types, deletion, interrupted delivery, bounded catch-up, revoked sessions, current grants and end-to-end stored rate/alert receipts. Existing NewMessage/MessageEdited handlers and local fixtures are not proof of these missing gates.
7. Deploy only reviewed fixed images with the normal guard, preserve other services and data, and record real-message and 24-hour monitoring evidence without secrets. Rotate a leaked session by revoking it in the account and generating a replacement privately.

# اتصال قیمتِ تلگرام — ۲.۸.۱۷

کدِ خواندن و تست‌های کد آماده‌اند؛ حساب و منبع واقعی حاضر نیستند. کاربر همین نبود را تأیید کرد. اتصال و دریافت واقعی پذیرفته نیست؛ خواندن روی سرور خاموش بماند. [دامنهٔ نسخه](telegram-release-2.8.17-fa.md).

## از مالک چه لازم است

| مورد | دقیق چه چیز |
| --- | --- |
| حساب خواننده | حساب تلگرام که اجازهٔ دیدن کانال و گروه منتخب را دارد؛ حساب ربات جای آن نیست |
| اطلاعات برنامه | `TELEGRAM_API_ID` و `TELEGRAM_API_HASH` از بخش API development در سامانهٔ رسمی `https://my.telegram.org` |
| نشست | `TELEGRAM_SESSION_STRING`؛ ابزارِ ورودِ پایین آن را در فایل خصوصی می‌نویسد؛ مالک کد و رمز دوم را فقط در پایانهٔ خصوصی خودش بزند |
| منابع | نخست یک کانال و یک گروه؛ نام عمومی یا شناسهٔ دقیق، ابزارهای مالی، چند نمونهٔ متن مجاز، و حقِ دریافت/ذخیره/نمایش/تاریخچه |
| منبع خصوصی کانالی | عضویتِ مجازِ همان حساب؛ اگر username ندارد، access hash همان حساب در نگاشتِ خصوصیِ `TELEGRAM_PEER_ACCESS_HASHES` لازم است؛ مقدار در گفتگو نیاید |

فایل خصوصیِ خالی ساخته شده و از Git کنار است:
`D:\Projects\Nerkhbaan\repo\.local-keys\telegram-ingestion.private.env`

سه کلیدِ اصلی فقط همان‌جا پُر شوند. شماره، کد ورود، رمز دوم، نشست، hash خصوصی و پیوند دعوت در گفتگو یا Git نیایند. نبودِ حساب با مقدار نمونه پوشانده نشود. `TELEGRAM_BOT_TOKEN` برای فرستادن هشدار است؛ خواندن قیمت را راه نمی‌اندازد.

## ساخت نشست، فقط با خودِ مالک

روی دستگاه خصوصیِ مالک، وابستگی‌های ثابت worker نصب و دو کلیدِ برنامه در فایل بالا پُر شوند. سپس از ریشهٔ مخزن:

```powershell
python apps/telegram_worker/login.py --env-file 'D:\Projects\Nerkhbaan\repo\.local-keys\telegram-ingestion.private.env'
```

ورود تعاملی فقط همین ابزارِ مالک است. مقدار نشست چاپ نمی‌شود؛ فایل به‌صورت اتمی جایگزین می‌شود. پایانهٔ شخصی با ضبط خروجی یا اشتراک صفحه نباشد. خودِ خدمت، `connect` و بررسی نشست دارد؛ ورود تعاملی و گرفتن کد تازه روی سرور ندارد.

## تنظیم پنل

1. در بخش منابع تلگرام، ابتدا منبع خاموش بساز. شناسهٔ عددی دقیق لازم است؛ username به‌تنهایی هویت منبع نیست. کانال و سوپرگروه، شناسهٔ علامت‌دار `-100…` دارند؛ گروه عادی شناسهٔ منفیِ خودش را نگه دارد. عدد مثبت برای گروه مبهم و مردود است.
2. نوع منبع، ابزار مجاز، پارسر `strict_explicit` یا `strict_hashtag`، نسخهٔ قالب، حد سن، اطمینان و اختلاف را تعیین کن. منبع تازه در API و فرم پیش‌فرض خاموش است. پیش‌نمایش با همان پارسر worker کار می‌کند.
3. قالب‌های صریح برای یازده ابزار بومی هست: طلای۱۸، طلای۲۴ با تصریح خلوص۹۹۹۹، نقره۹۹۹ و۹۲۵، دلار/تومان، تتر/تومان، بیت‌کوین/تومان، اونس طلا/دلار، اونس نقره/دلار، بیت‌کوین/دلار و تتر/دلار. نمونه‌ها در `apps/telegram_worker/tests/test_price_templates.py` هستند. `XAUUSD 4000 USD oz` نمونهٔ اونس است؛ گرم جای اونس نیست. نرخ مرجعِ محاسبه‌شده با نرخ مستقیم یکی نشود.
4. نقش‌ها `compare`، `verifier` و `fallback` هستند؛ مصرف نرخ فقط دو نقش آخر را می‌پذیرد. حدِ اعتمادِ شاهد۰٫۵ و جایگزین۰٫۸ است؛ افزایش اعتماد به منبعِ بی‌سند راهِ بستن تست نیست. شرط چند منبع، منشأهای مستقل می‌خواهد؛ دو بازنشر از یک منشأ یکی‌اند.
5. کلید سیاست `telegram_source_enabled` در تنظیم‌های عملیاتی، برای هر ابزار قابل کنترل است؛ پیش‌فرضِ کد اجازه می‌دهد، ولی حق مصرف، نقش، تازگی و منبعِ فعال هم لازم‌اند. پیش از قبولی، این سیاست و خودِ منبع خاموش نگه داشته شوند. مسیر مدیریت `PUT /api/admin/settings/operational` با مجوز مدیر است.
6. `TELEGRAM_CHANNELS` در این worker مصرف نمی‌شود؛ منابع از پایگاه و مجوزهای معتبر می‌آیند. تغییر منبع/خاموشی در بازخوانیِ حدود۵ثانیه‌ای دیده می‌شود؛ ذخیرهٔ SQL و مصرف API هم همان مرز را جدا می‌سنجند.

## حق مصرف و استقرار؛ کار مجری

- manifest با `schema_version=1`، محیط `production` و بخش `providers` لازم است. کلید هر منبع `telegram:<source_id>` است؛ عدد، شناسهٔ ردیف پایگاه است، شناسهٔ کانال نیست. `checked_at`، `expires_at` و مرجع HTTPS واقعی و معتبر لازم‌اند.
- خواندن `collect` و `store`؛ بازخوانیِ گذشته و بازیابی، `history` و `display` هم لازم دارد. این حق‌ها از عمومی‌بودن کانال یا عضویت نتیجه نشوند. حق‌های همهٔ منابع HTTP موجود حفظ شوند؛ manifest فقطِ تلگرام، قیمت‌های قبلی را از کار می‌اندازد.
- overlay `infra/compose.telegram.yaml` با `TELEGRAM_PRIVATE_ENV_FILE` و `TELEGRAM_RIGHTS_FILE`، فایل خصوصی و سندِ کامل حق را به worker و API می‌بندد. در worker، `TELEGRAM_STATE_PATH=/state/collector.json` و volume جدا برای پیوند حساب هست. تصویر ثابت و پروفایل `telegram` فقط پس از تست، بکاپ و بررسیِ نگهبان فعال شوند؛ دستور عمومیِ بازسازی همهٔ سرویس‌ها اجرا نشود.
- همان ده مهاجرت حفظ می‌شوند؛ مهاجرت تازه نیست. فعال‌سازیِ منبع، سند حق و profile، تغییر محیط جداست و رسید خودش را می‌خواهد. نصب API/پنلِ نسخهٔ تازه، فعال‌سازی خودکار تلگرام نیست.
- فایل پیوند حساب و volume آن هم با دسترسی محدود بکاپ شوند. حسابِ عوض‌شده رد می‌شود. اگر فایل پیوند گم شد و برای گروه عادی داده هست، نخست همان فایلِ معتبر بازیابی شود؛ حذفش برای دورزدن هویت راه‌حل نیست. سرویس تازه، گروه عادیِ دارای داده را بی‌پیوند تصاحب نکند.

## بازیابی و مرز تست

رویدادهای تازه و ویرایش/حذف پردازش می‌شوند. هر۳۰ثانیه، پیام‌های تازه با اجازهٔ تاریخچه دوباره سنجیده شوند؛ سقف پیش‌فرض۲۰۰ و بیشینه۵۰۰ است. کارها مستقل، تا چهار منبع هم‌زمان‌اند؛ سقف هر کار۹۰ثانیه است. صف پیام۲۵۶جا دارد. زمان انتظارِ محدودیت خدمت رعایت می‌شود؛ حساب یا مسیر برای دورزدن آن عوض نشود.

پیام قدیمی هشدار تازه نسازد. نسخهٔ دیررس، ساعتِ عوض‌شده و پیامِ حذف‌شده دوباره زنده نشوند. تغییر سیاست پارس، پیامِ بی‌تغییر را بازبینی کند. متنِ منفی/مبهم، واحدِ نامعلوم، عکس، صدا، بازنشرِ بی‌منشأ یا متن بیش از۴۰۰۰نویسه پذیرفته نمی‌شود. بازنشرِ معتبر، زمانِ اصلی را نگه می‌دارد.

حذفِ بی‌شناسهٔ گروه حدس زده نمی‌شود؛ پیام‌های ذخیره‌شدهٔ تازه، از همان گروه جدا پرسیده شوند. نبود پیام در صفحهٔ محدود، دلیل حذف نیست. خودِ تلگرام همهٔ حذف‌ها را همیشه خبر نمی‌دهد؛ [مرز رسمی رویداد حذف](https://docs.telethon.dev/en/stable/modules/events.html#telethon.events.messagedeleted.MessageDeleted). بازیابی، آرشیو کاملِ همهٔ گذشته نیست؛ قطعِ طولانی و عبور از سقف باید با شکاف واقعی ثبت شوند.

healthcheck تنها رسیدِ بازخوانیِ موفقِ حداکثر۱۸۰ثانیه‌ای می‌خواهد؛ صف پر، سقف بازیابی، خطا یا نبود رسید پاس نیست. سلامت خواندن، تازگی نرخِ بازار یا رسیدِ اعلان را ثابت نمی‌کند. پس از آماده‌شدن حساب و منبع، اتصال از محیط هدف، پیام و ویرایش/حذف واقعی، قطع/وصل، پایش۲۴ساعته و رسیدِ هشدار با مقصدِ مجاز جدا سنجیده شوند.
